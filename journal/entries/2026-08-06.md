# 2026-08-06

## 01:40 — milestone — The ledger is built: three bugs that nine review rounds missed

**What happened:** The ledger milestone is written and statically verified —
Aurora Serverless v2 at scale-to-zero behind the Data API, a
backend-for-frontend, four migrations, ten `SECURITY DEFINER` functions, and
the first real Shell and Pearl balances. Typecheck and build clean;
credential-free `cdk synth` succeeds for all three stacks with zero missing
context. Not yet deployed.

The plan went through **nine Codex rounds and 62 findings** before a line was
written. Then building it found three more that review could not have caught,
and the pattern in which is the point of this entry.

**1. The statement splitter mangled a migration.** The Data API rejects
multiple statements per call, so migration files are split. I wrote the
splitter to keep dollar-quoted PL/pgSQL bodies whole, tested it against
those, and it passed. Running it against the real migrations showed a
comment — *"the OAuth state; `binding_secret` is…"* — splitting
`CREATE TABLE login_attempts` in half. It understood `$$` but not line
comments, block comments or string literals. Four regions where a semicolon
is data, and I had handled one.

**2. The Pearl award paid nothing at the minimum stake.** The formula is
0.75 × stake × edge, which is **0.225 Pearls** on a 10-Shell bet. Pearls are
integers, so flooring each bet pays zero — measured over 560 bets, not a
rounding loss but **100% loss**. Wagering is the only source of Pearls
(`decisions/0005`), so a player betting the minimum would have been
permanently locked out of the cosmetic economy, while `currency-model.md`
frames minimum bets as the comeback floor. `bankroll.py` had it right all
along: it accumulates as a float. Fixed with a fractional carry on the player
row — verified across stakes and bet counts, exactly nothing lost, only
deferred (`decisions/0021`).

**3. The admin secret was still deletable.** Round 8 of the review caught
that a `SNAPSHOT` database with `DESTROY` secrets is a backup nobody can
open, and I applied the fix. Reading the *synthesized template* showed
`ClusterSecret … DeletionPolicy=Delete` — because `cluster.secret` returns
the secret **target attachment**, not the secret, so `applyRemovalPolicy` had
set Retain on a wrapper. The code looked correct and did nothing.

**Why it matters:** all three were invisible to review for the same reason.
A reviewer — human or model — checks what the artefact **says**. These were
defects in what it **does**: a parser meeting input it had not seen, an
arithmetic result below the smallest representable unit, an API returning a
different object than its name suggests. Nine rounds of adversarial reading
found 62 real problems and could not have found these, because reading was
never the tool that would surface them.

The corresponding discipline, now three-for-three in this project: after the
review passes, **run the thing and inspect the artefact**. Execute the parser
against real input. Compute the numbers and compare them to the simulation.
Read the CloudFormation template rather than the CDK that generated it.
Increment C's lesson was that a clean typecheck does not prove the program
runs; this is the same lesson one level down.

Also settled during the build and worth recording: `ec2.Vpc` performs an
availability-zones **context lookup**, which needs credentials CI
deliberately does not have — overriding `Stack.availabilityZones` removes it
rather than requiring a credentialed synth first. And the CDK default of one
NAT gateway per AZ (~$32/month each) was avoided explicitly; against a
project whose entire fixed cost is one hosted zone, nothing would have failed
and the bill would simply have arrived.

## 03:05 — milestone — The ledger is live: real balances, and ten bugs review could not find

**What happened:** The ledger milestone is deployed and working. A real
player signs in through the backend-for-frontend, passes the 18+ gate,
claims a daily login, and rolls dice — every movement an append-only ledger
row.

Verified against the live database after 32 economic events:

| Check | Result |
|---|---|
| Cached balance vs `SUM(ledger_entries)` | 44/9 vs 44/9 — **match** |
| Ledger composition | 31 `bet_stake`, 16 `bet_payout`, 9 `pearl_award`, 1 `task_claim` |
| Roll + range + content version stored (rule 5) | 31 of 31 |
| Idempotency keys | 32 — exactly one per economic event |
| `UPDATE ledger_entries` as the app role | **permission denied (42501)** |
| `SELECT * FROM sessions` as the app role | **permission denied (42501)** |

The fractional Pearl carry is visible in production: a winning 10-Shell bet
reports "0 Pearls (plus 0.794 carried)", and nine whole Pearls have since
been paid out as the carry crossed 1.0. Flooring per bet — the
implementation before `decisions/0021` — would have paid **zero, forever**.

**Why it matters: the review/execution split is now measured.** The plan
went through nine Codex rounds and 62 findings before a line was written.
Building and running it found **ten more**, and not one was a design flaw:

1. Statement splitter mangled a migration (comment containing a semicolon)
2. Pearl award floored to zero at minimum stake
3. Admin secret still deletable (`cluster.secret` is the *attachment*)
4. `cp` in a CDK hook — worked in Git Bash, failed in PowerShell
5. `bash` in an npm script — **same root cause, shipped anyway**
6. Routes never matched (`routeKey` is the registered pattern, not the path)
7. `callFunction` parsed non-JSON returns as JSON
8. Client secret granted but never fetched
9. Blanket `REVOKE` stripped pgcrypto from the definer role
10. Data API type mismatches — `timestamptz`, `uuid`, then `integer`

Every one is a boundary where my model of a tool differed from the tool.
The nine review rounds produced an architecture that absorbed all ten
without a structural change — the stack split, privilege model, idempotency
scheme, cold-start protocol and fractional carry all held. **Review and
execution find disjoint sets of defects**, and this milestone is the
clearest evidence of it the project has produced.

The most instructive was #5: I fixed `cp` and never asked where else I had
assumed a Unix shell. Fixing an instance is not removing the assumption.
